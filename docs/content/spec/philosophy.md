**AVIN** stands for **Abstraction, Versatility, Intuition and Naturalness**: four principles that
guide the design of the language.

Avin is designed to make sophisticated programming techniques accessible through a simple,
expressive and coherent language. Its philosophy is rooted in the belief that powerful software
should be possible to write without unnecessary complexity.

## A — Abstraction

*Express complex ideas simply.*

Abstraction lets programmers focus on what a program does rather than how every detail is
implemented.

Avin provides powerful abstraction mechanisms through classes, traits, generics, higher-order
functions and pattern matching.

The goal is not abstraction for its own sake, but abstractions that reduce complexity, encourage
reuse and make programs easier to understand.

**Principle:** Powerful abstractions should simplify code, not complicate it.

## V — Versatility

*One language, many possibilities.*

Avin supports several programming paradigms without forcing programmers into any single style.

Object-oriented, functional, imperative and generic programming coexist naturally, so developers
can choose the approach best suited to each problem.

Compiled to native code, with threads, futures and the system's libraries within reach, Avin is
intended for applications ranging from command-line utilities to sophisticated desktop software.

**Principle:** The language should adapt to the problem, not the other way around.

## I — Intuition

*Code should behave as you expect.*

A language becomes easier to learn and use when its features follow consistent, predictable rules.

Avin emphasizes a coherent type system, straightforward semantics, helpful type inference and
minimal syntactic surprises.

Common operations should require little ceremony, while advanced features should build naturally
on simpler ones.

**Principle:** The obvious way to express something should usually be the correct way.

## N — Naturalness

*Code that flows naturally.*

Naturalness is about making programs pleasant to write, read and maintain.

Avin favours concise, expressive syntax that resembles the way programmers think about problems.

Unnecessary punctuation, repetitive declarations, boilerplate and artificial distinctions should
be eliminated wherever possible.

The result should be code that communicates intent clearly, without obscuring its meaning behind
language machinery.

**Principle:** Writing code should feel like expressing an idea, not negotiating with a compiler.

## Four principles, one language

These principles reinforce one another:

- **Abstraction** provides expressive power.
- **Versatility** provides freedom of approach.
- **Intuition** provides predictability.
- **Naturalness** provides elegance.

Together they define Avin's central ambition: **a powerful, expressive programming language in
which sophisticated ideas can be expressed simply and naturally.** The [design choices](/spec/design/)
are how those principles become a type system, a runtime and a library.
